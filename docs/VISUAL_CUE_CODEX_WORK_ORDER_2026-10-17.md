## 2. 画像の絶対要件

- **背景透過のRGBA**。画像の外周に黒いにじみ、白縁、四角い背景や文字ラベルを作らない。
- **赤ちゃん本人の顔・全身は原則なし**。ミルクは哺乳瓶、本は本、手・足の動作は手・足を主役にする。抱っこ表現で人物が必要になったら無理に制作せず「レビュー待ち」にする。
- 1素材=基本1物体・1意味。スマホ内の約220–320 CSS px相当でも区別できる大きさと輪郭。
- 明るい色、自然なプロポーション、適度な簡略化（抽象すぎず、写実・人体が生々しすぎない）。デザインは `approved/` 4点を基準にする。
- **「ごはん」は白〜クリーム色のおかゆ**。スプーンの中身・器の中身を同色にする。緑のおかゆ `superseded/meal.webp` を使わない。
- 雨とシャワー、拍手と手を振る、飲むかどうかの質問と実際に飲む動作、「もう終わった？」と「終わった」を混同しない。

## 3. アニメーションはこの10種類を全部用意

Source of Truthは`asset-plan.json`。各行のvariantは共有パーツ利用を検討し、完成素材と不可なものは区別して報告。

| primitive | 制作要件・バリエーション |
| --- | --- |
| `motion.sip` | 哺乳瓶を傾ける。ミルクの上下関係が自然。飲み口が分かる。顔を描く必要なし |
| `motion.water` | お風呂の水・シャワー、雨粒の落下を明瞭に。雨は手のタップとは区別 |
| `motion.hand` | 拍手（両手接触・離れる）、手を振る（回転）、開閉、握る、数える（variant分け） |
| `motion.kick` | 左右の足が自然な付け根で交互に蹴る。手足を宙に不自然に変形させない |
| `motion.page` | 開いた絵本の**ページそのもの**が綴じ目を中心にめくれる |
| `motion.change` | 着替え・おむつ交換などの動き。無理に一枚で説明せず意味を保つ |
| `motion.hug` | ぎゅっと抱く動作。単なるハート点滅やクマの上下揺れは不可。意味が伝わらなければレビュー待ち |
| `motion.peekaboo` | 物を隠す→見せる。赤ちゃん全身を出さない |
| `motion.spoon` | **白いおかゆ**をすくう→持ち上げる→戻す。器・中身・スプーンに不自然な欠落がない |
| `motion.notes` | 音楽で音符が拍に合わせて移動・出現。点滅を避ける |

加えて `action.sleep` / `subject.rain` 等の静止でも意味が通るシーンは必要な範囲で控えめな動きを付ける。 `emma.*` 7状態は既存のEmma表情が流用可能か評価だけし、アプリに統合しない。

**動いてほしいパーツが実際に移動すること**が条件。イラスト全体を1～3px揺らすだけ、飾り・星・ハートだけ点滅させることは完成扱いにしない。以前のGIFは方法と動きの大きさの実験例であり採用済み完成品ではない。

## 4. 出力仕様

- 静止画像：透過WebP（編集用PNG原本も保持）、基準512×512、縦横の見切れなし。
- 動画：**透過animated WebPを第一候補**。意味が分かる構図で2.5～4.0秒自然にループ、原則10～16fps程度。編集が必要なものは部品別PNGと生成スクリプトも納品。
- 静止状態でも何の物体か分かること。Reduced Motion用の静止ポスターを必ず用意。
- サイズ目標：静止150KB以下、ループ動画400KB以下（ただし画質のための超過は記録・理由付け）。実際の端末で判断する。
- ファイル例：`assets/visual-cue/artwork/stills/{cue}.webp`、`animations/{cue}.webp`、`posters/{cue}.webp`。ZIPの`superseded`と`sprite-drafts`を本番素材と混同しない。
- `assets/visual-cue/artwork/manifest.json`：Cue ID/primitive、話題、イラスト、アニメ、poster、ループ長、制作元、状態(`draft`/`needs-review`/`accepted`)、検証結果。
- **完成できないものをダミー素材で埋めない**。 `needs-review` に残し、理由・代替案を記載。

## 5. 自動制作と検査

Codex+Mac単独でできる範囲を完結。Pillow、ffmpeg、Playwright等を使ってよい。再実行可能なスクリプトとREADMEを用意する。

1. ZIPのSHA256確認と内容展開（データはバックアップしてから）。
2. 素材状態の棚卸し表と不足リスト、優先順を出力。
3. 素材制作、部品を分離する場合のマスク・接合部・残像の検査。生成AIで新しい絵柄が必要なら、Codexが実際に使える画像生成手段を確認すること。**利用できない画像生成機能を装って完成とは言わない**。
4. アニメーションについて、複数フレームの差分（静止ではない）、動くパーツ面積・移動量、ループ末尾と先頭の滑らかさ、透明背景、実寸220～320pxでの視認性を自動テスト。
5. クラウドCIまたはMacで、ページ1画面1素材／一覧プレビューを自動キャプチャー。静止表現と動作の双方を人間が見て判断できる成果物を生成。
6. 錯視、部品の空中浮遊、変な手足の指、物体の欠落、青い水やおかゆの色不一致などをチェックし、検出した不具合を修正して再試験。
7. できたものを `assets/visual-cue/artwork/...` に格納し、**mainにマージせず**ドラフトPRを作成。画像一覧・動画プレビュー・対応表・未完了項目を添付。CI証跡を付ける。

## 6. 完了判定

- `asset-plan.json` の14 Illustrationと10 Animationの各コンセプトに完成候補があるか、未完が残るならその理由が明確。
- 言語・意味分類側の `visual-cue-assignments.draft.json` （914セット）には自動生成案が含まれ、人手で未レビューなものがあるため、**914/914の意味・品質が合格とは書かない**。素材制作と割当検証は別工程。
- すべての背景透過/動作/停止時表示をチェックし、静止画と動く動画を開いて比較できる。
- おかゆはクリーム色、2.5～4秒大きく自然な動作、文字やカード背景を画像に焼き付けない。
- 既存ユーザー向けアプリの挙動、Emma表示、設定、TTSは変化ゼロ（非ランタイム）。
- **完成の定義**は「採用候補一式を審査できること」であり、採用承認・一般公開を勝手に行わない。
