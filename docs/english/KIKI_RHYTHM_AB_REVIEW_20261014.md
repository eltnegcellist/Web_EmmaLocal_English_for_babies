# Kiki実音声A/B試聴（2026-10-14）

## 目的
通常会話の旧英文と、195セットのうち代表20組の改善英文を、実際の **Kitten Nano FP32・Kiki・設定速度0.8** で聴き比べます。辞書ベースの音素数・発音成功率は自然な抑揚の代替にはなりません。

## 実行方法
このPRのブランチをMacでチェックアウトし、リポジトリ直下で `python3 -m http.server 8765` を起動。ブラウザで `http://localhost:8765/kiki-rhythm-review.html` を開く。「音声モデルを準備」で音声モデルを読み込み、A/Bを再生。結果をJSONで保存します。

- 20組の旧新比較。文末 `!?` の処理はデフォルトで従来方式。
- 「実験：文末の ! と ? を維持する」をオンにすると同じ英文の文末記号を残す別方式が使えます。
- **アプリ本体は従来の区切り方式のままです**。既定TTSの挙動を変更しません。
- 個人の発話履歴・個人情報・音声録音をアップロードしない。すべて固定英文の生成テストです。
- 発音・抑揚・文末の疑問らしさ・短い繰り返しのリズム・音の自然さを記録してください。
- このツールは人手実聴の作業台であり、再生できたこと自体を「聴感良好」と評価しません。

## 発見した要確認事項
WebおよびAndroid実装では長年 `text.split(/[.!?]+/)` 相当の前処理により文末の疑問・感嘆記号が捨てられ、そのあと文末コンマが補われています。発話の上がり下がりやリズムに関わる可能性があるため、「文末記号維持」を実験オプションで比較します。既定方式の変更には実際の比較・Android版移植・端末検証が必要です。

## 検証の境界
`node scripts/test-kiki-ab.mjs` で20組の実バンクとの一致、旧式のままであるデフォルト、および実験分割時の!?維持を検証。**TTSのモデル推論を実行したという意味ではありません**。実音声生成はブラウザで行います。

## GitHub CI WAVサンプル
Web PR #91 のCIでは、固定英文だけを使い、ヘッドレスChromiumで実モデルのKiki生成を試行する。成功時は `kiki-rhythm-audio-ab` アーティファクトに、旧/新＋記号維持のWAV計6本、実時間・音量指標を収録する。ネットワークやモデル配布サーバーに左右されるため音声生成ステップは非必須。生成できても「イントネーションが自然」とは断定しない。元のユーザー音声は一切使用しない。

補足：文章区切りをブラウザ依存コードから独立した副作用のないモジュールへ移動し、モデルを読み込まずにNodeで旧方式・実験方式の回帰テストを実施します。
