# 多言語版みつことば：言語別モデル採用方針（2026-10-25）

> **意思決定の記録・研究用。** このブランチは main / 公開Web / Android の実装変更ではない。下記の「採用」は最適化方針・開発ターゲットの採択を意味し、WebAssembly実機で未確認の重みの配布承認や精度保証を意味しない。

## ユーザーの決定を最上位要件として固定

1. Moonshine採用。日本語の既存ルートを維持し、英語・ドイツ語にはMITのSmall Streamingを優先する。
2. Vosk採用。ただし言語ごとに精度を審査し、**韓国語VoskはCER 81.71%のため不採用**。フランス語Vosk Smallは良好な研究結果から優先採用候補。
3. タイ語専用ASRを採用対象に含める。先行調査の `sherpa-onnx-zipformer-thai-2024-06-20` を優先実装候補とする。非Streaming・モデルサイズ・タイ語自然音声の品質・Galaxy S25 WASM速度・モデル/学習データ利用条件は未確認。結果が基準を満たさなければ候補の差し替え、またはWhisper 5秒フォールバックとする。モデル未評価を「高速な製品採用済み」と表示しない。
4. E5各言語特化学習モデル/Interactionヘッドの導入方針を採用。**言語別に精度が上がった方式だけ選ぶ**。再学習Topicヘッドは既存検証で著しく悪化しているため不採用。
5. 認識精度、Topic/Interactionの意味保持、ASR+E5総遅延、端末メモリ・サイズ、ライセンスのいずれかで劣るモデルは本番選択から除く。速いが意味が違うモデルも不採用。
6. 多言語Whisperの目標コンテキストは**5秒**。5秒を超える音声はオーバーラップ分割と文の統合で全文を保持する。音声を5秒で強制切断・削除しない。

**重要：英語UIは英語認識固定ではない。** 現行 `src/multilingual/core.js` の `speechLanguage('en')===null` は多言語の自動検出を示す。初回言語不明時は短窓多言語Whisper等で言語推定し、確定した言語に応じ専用ASRへ移行する。検出された言語を会話中に再利用し、明示的な言語変更・誤検出から復旧可能にする。対象外言語を無理に英語Moonshineへ流さない。

研究で扱う中国語・ヒンディー語は現行UI六言語には未搭載。将来の追加承認と評価まで本番ルーティングへ無断追加しない。

## 「5秒Whisper」の正確な意味

- 現行本番 `Xenova/whisper-small` q8 + Transformers.js ONNXは音声が短くても**30秒分の特徴量コンテキスト**をエンコーダーへ渡す。入力PCMを5秒に切るだけでは5秒モデルとして高速化できない。
- 対象とするのは研究済みの **FUTO ACFT Whisper Small・5秒コンテキスト** + KVキャッシュ付きCPU/WASMデコーダー、または同等品質・速度を満たす5秒用モデル。
- 研究PR #143は5秒／10秒の適応窓を試している。今回のユーザー方針は多言語フォールバックを原則「5秒枠」とするため、5秒を超える発話は **最大5秒窓・250msオーバーラップ** で複数回処理して整合マージする。最大5秒を超える発話を破棄しない。オーバーラップ重複語の除去と文脈維持は未実装。
- ACFT Small 5秒の **Galaxy S25完成版の多言語ASR・精度・消費メモリの合格は未確認**。Whisper q8の1スレッド同一音声p50 11,216.59ms（RTF1.93）は30秒コンテキスト版のデータで、5秒ACFTの推論結果ではない。速くなることを未測定のまま断言しない。
- 5秒Whisperの実体が本番適格になるまでは既存稼働系を維持。言語モデルの単純な置換・推論未実装での配布は禁止する。

## E5特化学習の採用ルール

- 研究PR #146–147の結果は、人手検証0件の合成・翻訳文。**Topic=既存固定モデルを維持**、Interactionだけ比較対象とする。既存Topic＋共通再学習は凍結154例の両軸97/154、既存Topic＋各言語別再学習は96/154。言語別モデルの一括適用は全体スコアを下げる。
- *局所勝ち* を優先する暫定選定は en/de/ko → 言語別Interaction、fr/th → 共通再学習Interaction。タイ語/フランス語専用モデルは今後別データで改善した時に差し替える。研究で使われた独立言語特化**エンコーダー**（en bge, de gbert, fr CamemBERT, ko E5-KO, th E5-Thai等）も導入対象として維持するが、エンコーダー変更には**そのエンコーダーで再学習した両軸ヘッド**・モデルサイズ/CPU時間・盲検実録音での優位性が必要。名前に「特化」があるだけで採用しない。
- 韓国語13/22、タイ語共通16/22の意味両軸一致は本番の合格を意味しない。自然な保護者発話の否定／抱っこ／寝かしつけ／授乳／質問を新規評価する。
- ライセンス（モデル重み、音声学習データ、実行ランタイム）、端末メモリ、Web WASMの予測再現、初回DLとキャッシュ容量も各言語別に採用判定する。

## 実装・検証の順序（無駄な再比較を避ける）

1. **ルーティング仕様固定**：本ファイルと `research/multilingual-locale-optimization/policy.mjs` を使用。英語UI自動言語検出、韓国語Vosk除外、5秒窓超の継ぎ足しを回帰で保証する。
2. **確実に進められる組合せ**：日本語Moonshine維持、英語Moonshine実測成果再利用、ドイツ語Moonshine、フランス語VoskのWASM Worker配線を研究環境へ実装。各言語の最小資産のみ読み込む。
3. **タイ語専用ASR**：sherpa-onnx Thaiを端末内専用Workerに接続し、同一音声の正解・速度・5秒超の扱いを確認。重い/不正確なら採用ルートから除く。
4. **E5**：各言語の固定エンコーダーと対応ヘッドを厳密なSHAで結び、TopicとInteractionの実際のASR後の文字列に対する意味の正答率でゲート。現候補で悪化するfr/th言語別ヘッドは配布せず再学習対象とする。
5. **5秒Whisper**：小型版Whisper Baseへの精度無検証置換は禁止。ACFT Small 5秒実音声のCPU/WASM復元、オーバーラップ分割・マージ、言語検出・保持・切替を研究実装。語尾の欠落／否定反転など安全上重要な意味誤りを調査する。
6. **導入判断**：同一の人手校正済み実録音を使いASR CER/WERだけでなく、誤意味判定、正味p50/p95、RTF、発話確定後遅延、初回ロード、RAM、モデル容量のすべてで言語別の優劣を決定。優位でないモデルは明示的に除外する。製品 main への統合は別PRで行う。
