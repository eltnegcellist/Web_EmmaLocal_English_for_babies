## 今回の修正

利用者から、追加した身振りでは現在のmainより表情の情報が減り、手を出すだけでは意味が分からないとの評価がありました。**7種類の顔・手の差し替え案を撤回**し、既存Emmaの後ろに背景を添える方式へ変更しました。

- **Emmaの顔・まばたき・声に応じた口の動きを維持。** 最新main `b2536ab`の12素材、および`avatarFrameName / renderAvatarFrame / startAvatarBlinkLoop`の処理と一致しています。新しい顔のSVGへ置き換えません。
- 「安心」にはハート、「ほめる」には星の**2候補**を制作。顔の後ろの余白に置き、顔・目・口や表示サイズを変えません。意味が伝わるかは利用者の確認待ちです。
- 待機・にっこり・聞く・たずねる・誘うは従来のEmmaを使用。分かりにくい手や、意味の根拠がない記号を足して完成扱いにしません。
- 旧7点は`assets/emma-gestures/manifest.json`で`withdrawn`とし、実行時・新しいプレビューから除外。制作履歴と過去の描画検証を保存しています。技術検査の成功は意味の承認ではありません。

## アプリUI

「設定 → 見た目 → 英語を話している間の表示」で選びます。初期値は従来のEmmaです。対象物を表す採用済みイラスト・動画は従来どおりEmma領域に表示しますが、Emmaによる応答では既存の顔を表示したまま、対応する背景だけを加えます。

背景は音声開始に連動し、終了・停止・エラー・タブ非表示で消えます。「イラスト・背景を動かす」をオフ、またはOS reduced-motion設定では背景を静止表示。**この切替で既存のまばたき・口パクを止めません。** 未知英文や画像失敗の場合も従来Emmaを維持します。音声を画像の読み込み待ちにしません。

3文の録音は1ファイルで、確実な文ごとの時刻がありません。応答全体に1つの表示を使い、架空の均等な文境界を作りません。

## 検証

- 最新mainとの顔素材12点・まばたき/描画処理の一致を確認。
- `npm test`成功。プレビューと本体のフレーム選択27組、および音声RMSの閾値の一致を追加検証。
- Chromeブラウザ34項目成功。220/256/320pxで背景の有無による顔の位置・大きさの不変を確認。
- 実AACの音声でsmall/medium/largeの口、半目/閉眼のまばたきを検出。背景の静止中、背景なしとの比較中にも維持されることを確認。
- mainの顔を隠さず背景が後ろに出ること、音声終了・停止・話題変更で背景が消えること、スマホ幅・本体の「泣く・ぐずぐず」再生を確認。ページ例外0。
- 背景SVG4ファイルのXML、背景・実行時カタログの保留除外、読み込み失敗、古い応答の終了や読込の無視なども検証。
