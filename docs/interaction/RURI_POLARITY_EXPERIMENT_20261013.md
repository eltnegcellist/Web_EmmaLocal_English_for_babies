# Ruri-only 日本語否定判定：学習・再評価結果（2026-10-13）

**結論：公開版への導入は見送り。** 日本語キーワード・否定正規表現は使わず、Ruri v3 70M INT8から得た384次元ベクトルに二値ロジスティック回帰ヘッドを学習させる実験を行った。

## 固定した実験手順

- 学習・開発・評価：手作り肯定・否定の57対＝114文。**同じ意味ファミリーは必ず同じ分割へ**（train 74、dev 20、test 20）。
- 別比較：以前に確認済みの67日本語例は**学習にも選択にも使わない**が、すでに人間が結果を見た探索例なので独立な最終精度とは呼ばない。
- さらに難しい課題：新たに51例。事実否定25例＋「泣かないでね」「一緒に読まない？」などの依頼・提案・安心させる文26例。
- Ruri ONNX本体のパラメータを変更せず、線形分類ヘッドのみ学習。
- 開発データのみで正則化 `C` と否定採用閾値を選択。後から難問51例に合わせて調整していない。
- 再現：`node scripts/extract-ruri-polarity-embeddings.mjs` → `python3 scripts/train-ruri-polarity-head.py`
- 実際の成功CI: [GitHub Actions #38316616095](https://github.com/eltnegcellist/Web_EmmaLocal_English_for_babies/actions/runs/38316616095)。ヘッドはCIの `polarity-experiment` 成果物内のみ。**Web/Androidのランタイムには未導入。**

## 数値結果

| 分割 | 正解 | 正解率 | 否定適合率 | 否定再現率 |
|---|---:|---:|---:|---:|
| 同じ文型が多い人工ファミリー分割テスト | 20/20 | 100.0% | 100.0% | 100.0% |
| 既に分析済みの追加67例（比較のみ） | 66/67 | 98.5% | 92.3% | 100.0% |
| **新規・難しい51例** | **35/51** | **68.6%** | **62.9%** | **88.0%** |

51件のうち16件を間違えた。実際には否定しているのに否定と判定できないもの3件、否定された事実ではないのに否定と扱うもの13件。

### 誤分類の代表例

| 日本語 | 期待する扱い | 誤判定 |
|---|---|---|
| もう泣かなくなったよ | 泣いている状態ではない | 否定を見逃す |
| もう眠くなくなったよ | 今は眠いわけではない | 否定を見逃す |
| 終わりそうだけど、まだ終わらないね | まだ未完了 | 否定を見逃す |
| 泣かないでね、大丈夫だよ | 安心させる言葉 | 否定された事実と誤判定 |
| 絵本を一緒に読まない？ | 読むことへの誘い | 否定された事実と誤判定 |
| ミルクを少し飲まない？ | 授乳の提案 | 否定された事実と誤判定 |
| 頑張ったけどできなかったね、大丈夫だよ | 成功は否定・主たる働きかけは安心 | 文全体を否定と誤判定 |
| 終わらなくても、頑張ってるね | 完了していないが努力を認める | 文全体を否定と誤判定 |

**問題の本質：** 「否定を含む文章」と「否定された事実を主たる意味として伝える文章」は異なる。また否定の影響範囲はTopic軸とInteraction軸で違う。「泣かないで、大丈夫だよ」で`cry`を避ける必要はあっても、`reassurance`を棄却してはいけない。

現状の二値分類器は**1文1ラベル**であり、主節、提案、助言、安心させる表現と状態の否定を同時に扱えない。単なる閾値上げや、この51例を後から学習に混ぜて「正解率が上がった」と評価するのは不適切。

## 次の改善案（設計のみ、未実装）

1. **否定による事実反転の対象をラベルとして明確化**し、例えば `cry:negated`, `sleep:negated`, `finish:negated` などのクラス、または軸ごとのスコープ情報をRuri埋め込みから推定する方式を小さく比較する。キーワード・正規表現で判定しない。
2. `not crying but reassuring`, `not done but trying`, `would you like to read?` のような複合・反転・否定疑問を**各Topic×Interaction別に**人手で審査したうえで教師データに加える。
3. 文型（semantic family）と録音話者を別単位として分割した未知データを最低数十件作成。今回の51件は分析済みなので次の最終テストへ再利用しない。
4. 実際のMoonshineの認識出力を使って、`Ruri Topic + Interaction → 英文` の**意味の一致**を第三者が判定する。必要なら保護者の同意のある音声を端末ローカルで採点し、生音声をGitHubへアップロードしない。
5. この実験ヘッドを**本番にコピーしてはいけない**。PR-D/Eの既存ヘッドを維持し、独立評価に合格した設計だけを別のPRとして採用する。
