# 実装したアプリ本体の専用URL

ユーザーの「確認用ページではなく、実際に実装したページを見たい」という依頼に対応し、専用Pagesの `app/` に通常のアプリを追加する。mainへのマージはしない。

- 正本の `index.html` と `src/app.js` を使用。試作フラグ、英文選択パネル、初回準備の省略、マイク起動の制限を付けない。
- 初回準備、マイク会話、押して聞く、履歴、設定を通常どおり使う。Visual Cueの初期オンも同じ設定実装で動く。
- 実行時コード、録音バンク、Visual Cue素材に加え、Silero、Ruriのモデルと実行環境、多言語の実行環境とヘッド、ライセンスを配布する。大きいWhisper/E5/Moonshineの取得元は本体と同じ固定リビジョンを使用する。
- パッケージ作成時にRuriの全配信資産とSileroのSHA256を確認する。

## 保存先とService Worker

GitHub Pagesは同一アカウントの各プロジェクトでオリジンを共有するため、このURLの設定と会話履歴を別保存先にする。画面、会話処理、音声処理の実装は変えない。

配信するHTMLには同期起動する `app-instance.js` を1つ追加する。Local/Session Storageは `emma_visual_cue_app_v1:` の接頭辞を使い、会話履歴だけを別IndexedDBへ向ける。初回準備完了フラグやマイク許可は既存アプリからコピーしない。公開モデルの分割保存領域は同じままにし、モデルWorkerとの互換性を維持する。

Service Workerは `app/` のスコープだけを制御し、画面キャッシュ名も別にする。リセットページも当該設定・履歴・画面キャッシュだけを対象とし、他のPagesアプリを登録解除・初期化しない。検証済みの共有音声・モデルは再利用する旨を表示する。

`deployment.json` の `fullApplication` は `app/`、`applicationDeployed` はtrue。本番mainの更新とは区別し、`productionApplicationDeployed` と `mainMerged` はfalse。配布全ファイルのSHA256を記録する。

## 検証の区別

保存先の分離をJSDOMで検査する。ブラウザでは通常の初期画面、試作パネルなし、初期オン、Service Worker、ASR用の分離ヘッダー、設定保存、モバイル、実録音と顔あり抱っこ動画を検査する。

ブラウザの再利用者向けテストだけはテスト操作で準備済みの保存値を作る。配布するHTML/JSにはその省略処理を含めない。初回のモデル準備全体や実マイクの連続会話を実施済みとは扱わない。
